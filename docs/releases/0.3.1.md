Tessera 0.3.1 fixes agent visibility and several desktop workflow issues from 0.3.0.

- **Agents appear before their first turn:** Overview discovers local Codex and Claude processes launched inside Tessera panes, even before lifecycle hooks arrive. These rows are labelled Untracked, not Running; discovery never guesses approval or turn state. The first hook upgrades the same row and preserves selection.
- **Reliable Codex setup:** the setup guide recommends `codex --no-daemon` so hooks use the current pane's environment rather than a shared daemon's old socket. Hooks still require review and trust through `/hooks`.
- **New workspace directories:** the workspace creation form creates missing directories, keeps the optional display name separate, and preserves entered values when creation fails.
- **Startup appearance and shortcuts:** saved theme preferences apply on the first frame, and the status bar makes its shortcuts clearer.

Process discovery runs in a background worker at most every two seconds. It reads only process IDs, parent IDs, and executable names. It does not read command arguments, environments, prompts, or transcripts. Agents outside Tessera and remote agents remain outside discovery's scope.

Install or update after the release is published:

```sh
curl -fsSL https://github.com/JeremySomsouk/tessera/releases/latest/download/install.sh | sh
```

Preferences and session history remain compatible. Lifecycle hooks remain an explicit installation step. Existing macOS installations can receive the signed updater release on quit; Linux installations update by rerunning the installer. Every Tessera launch still opens a fresh terminal rather than restoring live panes.

Release preparation does not publish a tag or release. Native interactive, VoiceOver, Linux package, and installed automatic-update acceptance remain pending.
